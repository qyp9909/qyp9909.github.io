下面记录具体原理、配置方法和常见问题。

有些内网页面在自己的电脑上打不开，但服务器可以访问。我目前的使用方式是：先连接 VPN，再通过 bastion 跳板机连接 server-09，在本机建立 SOCKS5 代理，最后启动一个使用该代理的 Chrome 浏览器。

这篇文章记录完整步骤，也说明两个容易混淆的地方：server-09 到底是什么，以及能不能直接把它换成服务器 IP。

所以，server-09 不只是“服务器地址的缩写”，还可以一起带上用户名、端口、密钥和跳板机等设置。server-xx 只是命名习惯，并不是 SSH 的特殊语法。配置规则见 OpenSSH 的 ssh_config 手册。

第三步：建立本地 SOCKS5 代理

在本机 PowerShell 中执行：

  • -N：不执行远程命令，只维持转发连接。
  • -D 127.0.0.1:1080：在本机的 1080 端口建立动态 SOCKS 代理，监听地址限定为本机回环地址。
  • server-09：SSH 最终登录的目标，跳板路径由配置中的 ProxyJump 决定。

相关参数见 OpenSSH 的 ssh 命令手册。

按提示完成认证。如果跳板机和目标服务器都使用密码登录，可能分别提示输入两次密码；配置了密钥时，也可能不需要输入登录密码。第一次连接时，还可能需要核对并确认主机指纹。

认证完成后，终端通常会停在那里，没有远程命令提示符。这是正常现象：SSH 正在前台保持隧道运行。

这里的“挂着”是保持进程运行，不是暂停进程，也不是关闭终端。 接下来新开一个本机 PowerShell 窗口。

两个 Chrome 参数分别用于：

  • --user-data-dir：指定独立的用户数据目录 Chrome-SSH，保存这组浏览器窗口的 Cookie、历史记录等数据，便于与日常使用的 Chrome 分开。

直接执行 ssh -N -D 127.0.0.1:1080 10.0.0.9，通常不会继承只写在 Host server-09 下的配置。 SSH 的 Host 匹配通常基于命令中给出的名称，而不是反向查找哪个别名的 HostName 等于这个 IP。其他能匹配 IP 的配置块或通配规则仍可能生效。

因此，在已经配置好别名的情况下，继续使用 server-09 最省事。也不要为了简化命令把最终目标改为 bastion，否则网页请求的出口会变成跳板机。以上行为可对照 SSH 配置中的 Host、HostName 和 ProxyJump 理解。

使用结束与常见问题

使用结束后，关闭专用 Chrome，回到运行 SSH 的终端按 Ctrl+C 结束隧道，再按需断开 VPN。

现象 优先检查
连接超时 VPN 是否正常、跳板地址是否可达、目标 IP 和端口是否正确
Permission denied 提示对应跳板机还是目标服务器，用户名、密码或密钥是否正确
Address already in use 本机 1080 是否被占用；若改用 1081，SSH 和 Chrome 中都要同步修改
ERR_PROXY_CONNECTION_FAILED SSH 是否仍在运行，Chrome 代理地址和端口是否一致
SSH 能登录，但打开网页时提示 administratively prohibited 服务端是否允许 TCP 转发，以及目标地址是否受转发策略限制
只有某个内网页面打不开 server-09 能否访问该地址，服务端口、DNS 和网站权限是否正常
